# Contributing to @noisedlabs/sdk

Thank you for helping. Noised moves other people's money, and this SDK builds the transactions they sign and the reports they trust, so changes are held to a high bar. **Report vulnerabilities privately ([SECURITY.md](SECURITY.md)), never in a public issue or pull request.**

## Setup

You need Node.js 22.12 or later and pnpm 11.8 (`corepack enable` picks the version pinned in `package.json`).

```bash
cd sdk
pnpm install --frozen-lockfile
pnpm typecheck      # tsc --noEmit over src/ and test/, then examples/ (examples/tsconfig.json)
pnpm test           # vitest run: no network
pnpm build          # dist/: ESM, .d.ts, source maps and the IDL JSON files
```

All three must pass before a pull request is reviewed.

### On Windows

Keep the pnpm store, caches and `node_modules` on a drive with enough free space. The project's configuration sets no store, cache or state directory: to put them elsewhere, set the `pnpm_config_store_dir`, `pnpm_config_cache_dir` and `pnpm_config_state_dir` environment variables, or run `pnpm config set -g store-dir <dir>`. If you made `sdk\node_modules` a link to another drive, do not delete it by hand. If you keep a toolchain env script, load it first:

```powershell
. $env:NOISED_ENV_SCRIPT   # optional: your toolchain env script (MSVC, Agave 4.3.0, caches)
cd sdk
pnpm install --frozen-lockfile; pnpm typecheck; pnpm test; pnpm build
```

## Where the truth lives

The SDK mirrors the on-chain programs; it never defines the protocol. When they disagree, the programs win:

- `programs/` (launchpad, hook, vault, shield, autopilot): instructions, accounts, errors, constants, PDA seeds. `test/sources.test.ts` re-reads the Rust sources and fails when a constant, seed, error or IDL in the SDK drifts.
- `crates/noised-lmots`: LM-OTS and LMS signing and verification.
- `tests/integration/vectors/*.json`: byte-exact vectors produced by the Rust code. The SDK's copies in `test/vectors/` must stay byte-identical (the tests never read outside `sdk/`).

## Coding rules

- TypeScript `strict` (plus `noUncheckedIndexedAccess` and friends, see `tsconfig.json`), ES modules, relative imports with a `.js` suffix.
- `bigint` for every u64, u128 and i64 (lamports, token amounts, slots, unix timestamps); `number` only for values that fit u32. Times are unix seconds.
- Encode and decode through the IDLs (`src/idl/`, `IdlCodec`), never with hand-written byte offsets that the IDL could give. Where an offset is documented (account layouts in doc comments), a test checks it against a Rust-produced account.
- Refuse before signing: a builder throws on anything the program would refuse deterministically, and every post-quantum signer checks the cluster, the key's index and the one-message-per-key rule before a signature exists.
- Doc comments state the security rule a function enforces or relies on (what it refuses and why), not only what it returns.
- Errors are plain English and name the program error they pre-empt (`"CapExceeded: …"`).
- No new runtime dependency unless it is unavoidable. `@noble/hashes` already gives SHA-256, HMAC and HKDF; `@scure/bip39` gives BIP-39.

### Supply chain

`pnpm-workspace.yaml` enforces exact pins, versions at least 7 days old (`minimumReleaseAge: 10080`), `trustPolicy: no-downgrade` (one reviewed exception: `undici-types@6.21.0`, type declarations only), registry-only transitive dependencies, no install scripts, and `overrides` that keep one copy of `@solana/web3.js`, `@coral-xyz/anchor` and `@solana/spl-token` in this workspace. `@solana/web3.js` is the package's one **peer dependency** (`^1.98.4`, and an exact dev dependency here): the API takes and returns its objects, so an app provides it and the SDK's `instanceof PublicKey` / `Transaction` checks see the app's own classes. The range must admit the current 1.x client stack (`@solana/wallet-adapter-base` 0.9.28 needs `^1.99.0`; a tighter range makes npm stop with ERESOLVE). `@solana/spl-token` and `@coral-xyz/anchor` are ordinary exact dependencies: none of their objects crosses the API (anchor only supplies `BN` to Meteora's quote functions inside `buildSwapTx`). `test/package.test.ts` pins this arrangement. Meteora's SDK is loaded with a dynamic `import()` only by `buildSwapTx`. A dependency change needs a reason in the pull request and a reviewed lockfile diff.

## Tests

- **Every test is a regression test:** it must fail without the code it covers. For security-relevant code, check it by breaking the code on purpose (a mutation) and watching the test fail; the post-quantum and launch modules were checked this way, mutant by mutant.
- **Byte parity with Rust** for every encoder, hasher and signer, through the vectors in `test/vectors/`.
- **No network.** RPC calls go to mocked connections (`test/helpers.ts`, `test/world.ts`, `test/attest_world.ts`, `test/verifyFixtures.ts`, `test/qslFixtures.ts`).
- Tests read nothing outside `sdk/` except `sources.test.ts`, which reads the Rust sources it checks the SDK against.

### Regenerating IDLs and vectors

After a program change, regenerate the five Noised IDLs (anchor-cli 1.2.1). Put build output on a drive with enough free space (tens of GB):

```powershell
. $env:NOISED_ENV_SCRIPT   # optional: your toolchain env script (MSVC, Agave 4.3.0, caches)
$env:CARGO_BUILD_JOBS = '4'; $env:CARGO_TARGET_DIR = "$env:NOISED_BUILD_ROOT\target-sdk\root"
foreach ($p in 'noised_vault', 'noised_hook', 'noised_launchpad', 'noised_shield', 'noised_autopilot') { anchor idl build -p $p -o "sdk\src\idl\$p.json" }
```

`dynamic_bonding_curve.json` and `cp_amm.json` are vendored copies of Meteora's IDLs (from `idls/`), under Meteora's MIT license: its text, with Meteora's copyright line, is `src/idl/LICENSE-meteora` (published with `src/`, and named in `NOTICE`). Keep it next to them.

The programmable module's parity vectors are copies of `crates/noised-rules/tests/vectors/{rules,graph,differential}.json` in `test/vectors/programmable/`, pinned by SHA-256 in `test/programmable/vectorFiles.ts` (copy the crate's files and update the pins together). `test/vectors/programmable/autopilot.json` is written by the autopilot program's own functions: copy `test/vectors/programmable/autopilot.gen.rs` to `programs/noised-autopilot/src/tests/sdk_vectors.rs` in a scratch copy of the workspace, add `mod sdk_vectors;` to `src/tests/mod.rs`, run `SDK_VECTORS_OUT=<file> cargo test -p noised-autopilot --lib write_sdk_vectors`, copy the file and update its pin in `test/programmable/autopilot.vectors.test.ts`.

The vault vectors (`tests/integration/vectors/vault_withdraw.json`, written by `tests/integration/tests/sdk_vectors.rs`) are regenerated after a deliberate format change with:

```powershell
. $env:NOISED_ENV_SCRIPT   # optional: your toolchain env script (MSVC, Agave 4.3.0, caches)
$env:CARGO_TARGET_DIR = "$env:NOISED_BUILD_ROOT\target-sdk\it"; $env:NOISED_WRITE_SDK_VECTORS = '1'
cargo test --locked --manifest-path tests/integration/Cargo.toml --test sdk_vectors
```

Without the variable, that Rust test fails if the committed file is stale. The LMS vectors (`tests/integration/vectors/lms.json`) are written by `tests/integration/tests/lms_vectors.rs` from `noised-lmots`, the metadata vectors (`tests/integration/vectors/metadata.json`: the records, invalid records with their errors, PDAs, account bytes, token uris, publish data and events, the vector icon, the typical record's attestation and `launch`) by `tests/integration/tests/metadata_vectors.rs`, and both are landed on the launchpad build by `vectors_onchain.rs` (an independent check: `python -I scripts/pq/lms_reference.py metadata-vectors tests/integration/vectors/metadata.json`). Copy regenerated vector files into `sdk/test/vectors/` unchanged.

## Examples

`examples/` must keep type-checking (`pnpm typecheck` runs `examples/tsconfig.json`, which maps `@noisedlabs/sdk` to `src/`). When an API changes, update the examples and the README's quickstart in the same pull request. The tests never run the examples: they talk to an RPC.

## Pull requests

- One topic per pull request, with the reason for the change and, for a protocol change, the program change it mirrors.
- `pnpm typecheck`, `pnpm test` and `pnpm build` pass; new code comes with regression tests; vectors are byte-identical copies.
- Public API changes are listed in [CHANGELOG.md](CHANGELOG.md) under "Unreleased", with "BREAKING" where callers must change.

## Releasing (maintainers)

1. Move the "Unreleased" changelog entries under the new version and bump `version` in `package.json`.
2. `pnpm install --frozen-lockfile && pnpm typecheck && pnpm test && pnpm build`.
3. `pnpm pack` and inspect the tarball (`tar -tzf noised-sdk-<version>.tgz`): only `package.json`, `README.md`, `LICENSE`, `NOTICE`, `CHANGELOG.md`, `SECURITY.md`, `dist/` and `src/`. No tests, vectors, keys, `.env` files or local paths.
4. Install the tarball into a scratch consumer project that provides its own `@solana/web3.js`, and check there: it resolves to ONE package directory, the consumer's (from the consumer, from inside the SDK and from the SDK's `@solana/spl-token`), and the SDK's `PublicKey`s are `instanceof` the consumer's class (and the consumer's are accepted); `src/idl/LICENSE-meteora` and `NOTICE` are in the tarball; no public path reaches a raw one-time signer (`lmots` has no `sign` / `signDeterministic`; deep imports such as `@noisedlabs/sdk/dist/pq/lmots.js` fail with `ERR_PACKAGE_PATH_NOT_EXPORTED`); the types compile under `moduleResolution` `nodenext` and `bundler`.
5. Publishing is done only by `.github/workflows/release.yml` when the owner pushes a version tag on `main` (npm provenance through trusted publishing; see that file's header for the one-time setup), never from a laptop. `scripts/release/prepare-publish.mjs` checks the package first.

### Pre-publication checklist (owner decisions, before the repository or the package goes public)

- [x] **Remove machine-specific paths from the package-manager configuration.** Done: `sdk/pnpm-workspace.yaml` and `sdk/.npmrc` set no store, cache or state directory, and every supply-chain setting stays in those files (see Setup, "On Windows").
- [x] npm scope `@noised`; `"private": false` with `publishConfig` (public, provenance); the security contact is `security@noised.fun`.
- [ ] Set the GitHub owner in `scripts/release/repo-config.json`, then run `node scripts/release/apply-repo-config.mjs`: it writes the repository URLs into every `package.json`, the root `Cargo.toml` and the README badges. Create the `security@noised.fun` mailbox.
- [ ] Name the copyright holder in `NOTICE` (and the repository root's `NOTICE`) if "The Noised authors" is not what you want. (The MIT license text of the vendored Meteora IDLs is in `src/idl/LICENSE-meteora`; an app that bundles the IDLs into its own build must carry that text too.)
- [ ] Steps 1 to 4 above, from a clean checkout in CI.
